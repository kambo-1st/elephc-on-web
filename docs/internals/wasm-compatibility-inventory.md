This inventory tracks elephc's PHP-facing feature surface and the current
`wasm32-web` status. The rule for this backend is conservative: a feature is
only marked supported when a wasm e2e test compares its output with the PHP CLI
oracle. Unsupported dynamic forms must fail with a diagnostic rather than
silently compiling to different behavior.

Status keys:

- **Wasm yes**: supported by wasm e2e oracle tests.
- **Wasm partial**: some forms work, but important elephc-supported forms are missing.
- **Wasm no**: elephc supports this natively, but wasm has no lowering yet.
- **Extension**: elephc-only feature with no PHP-oracle comparison target; use native elephc behavior as the reference.

## Current Priority

1. **Strings**: move from literal-only helpers to string variables and runtime string values.
2. **Arrays**: indexed arrays first, then associative arrays, then array builtins.
3. **Classes and objects**: properties, constructors, methods, inheritance, interfaces.
4. **Functions and callables**: closures, variadics, spread, callable variables, first-class callables.
5. **JSON and mixed**: use array/object work to unlock full JSON compatibility.
6. **Control flow and exceptions**: finish PHP control-flow forms not covered by wasm.
7. **System, IO, regex, SPL, generators, fibers, and extensions**: later chunks after heap/runtime support exists.

## Work Chunk Order

1. Runtime string values and output transforms.
2. Indexed arrays: literals, `count`, reads, writes, `foreach`.
3. Indexed array builtins without callbacks.
4. Associative arrays and string keys.
5. Array/string bridge builtins: `explode`, `implode`, `str_split`.
6. General string allocation: concat, function returns, variable assignment from builtins.
7. Classes: direct properties, constructors, methods.
8. Inheritance/interfaces/traits/enums.
9. JSON decode/encode with arrays, objects, and mixed.
10. Closures/callables/spread/variadics.
11. Exceptions.
12. IO/system/regex/SPL/generators/fibers/extensions.
